# Неделя 3 (часть 1): модуль геокодинга — впрок, до получения ключа

Ключ Яндекс.Геокодера ещё не получен, поэтому подготовил модуль так, чтобы
подключение свелось к одной строке в `.env` — код и тесты уже готовы и
проверены на моках.

## Что сделано

- `backend/app/geocoding.py`:
  - `geocode_address(address) -> Координаты | None` — обращается к
    HTTP Геокодеру Яндекса, кэширует результаты (`lru_cache`), не падает,
    если адрес пустой или ключ не настроен.
  - `is_configured()` — проверка, задан ли `YANDEX_GEOCODER_API_KEY`.
  - `geocode_many(addresses)` — геокодит список, изолирует ошибки по
    отдельным адресам (один битый адрес не роняет остальные).
  - `GeocoderError` — исключение для сетевых/форматных ошибок; вызывающий
    код должен превращать его в предупреждение, а не падать.
  - `haversine_km(a, b)` — расстояние по прямой между координатами,
    заготовка для следующего шага («Валидация маршрута»).
  - `set_client()` — точка расширения для тестов (подмена HTTP-транспорта).

- `backend/tests/test_geocoding.py` — 9 тестов на моках `httpx.MockTransport`:
  успешный геокодинг, пустой адрес, адрес не найден, битый ответ API,
  HTTP-ошибка (403 и т.п.), изоляция ошибок в `geocode_many`, корректность
  `haversine_km` (Москва–СПб ≈ 635 км по прямой).

- `backend/.env.example` — куда вписать `YANDEX_GEOCODER_API_KEY` и
  `ALLOWED_ORIGINS`. Сам `.env` в git не попадёт (уже в `.gitignore`).

- `backend/requirements.txt` — добавлен `httpx` (HTTP-клиент для запросов
  к Геокодеру).

Итого тестов в проекте: **49**, все зелёные (`pytest -v`).

## Как подключить, когда придёт ключ

```bash
cd backend
cp .env.example .env
# вписать в .env: YANDEX_GEOCODER_API_KEY=<ключ>
```

При запуске через `uvicorn` переменные окружения из `.env` нужно будет
подхватывать (например, через `python-dotenv` или экспортировать в shell) —
это добавим отдельным шагом, когда ключ будет на руках и начнём реально
вызывать геокодер из `calc.py`.
