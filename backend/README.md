# Калькулятор ГСМ — бэкенд (неделя 1: алгоритм + API)

FastAPI-бэкенд для расчёта путевых листов. Логика 1:1 портирована из
`src/calc.ts` фронтенда — числа сходятся между клиентом и сервером.

## Запуск

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Swagger-документация: http://localhost:8000/docs

## Эндпоинты

- `GET /api/health` — проверка живости.
- `POST /api/calculate` — принимает `ВходныеДанные` (см. `app/schemas.py`,
  поля названы так же, как в `src/types.ts` фронта), возвращает
  `РезультатРасчёта` (список путевых листов + предупреждения + сводку расхода).

## Валидация (`app/schemas.py`)

Помимо типов и обязательности полей, на уровне pydantic-модели `ВходныеДанные`
проверяется:

- `периодПо` не раньше `периодС`;
- для спецтехники обязателен ручной средний расход;
- список водителей не пуст;
- для междугородного/международного сообщения указан срок рейса;
- рабочие дни водителей и даты заправок попадают в расчётный период.

При ошибке валидации FastAPI возвращает `422` с человекочитаемым списком
сообщений в `detail` (см. `app/main.py: validation_exception_handler`).

## Структура

```
backend/
├─ requirements.txt
└─ app/
   ├─ main.py      # FastAPI app, CORS, обработчик ошибок валидации
   ├─ routes.py     # POST /api/calculate, GET /api/health
   ├─ schemas.py    # pydantic-модели входа/выхода
   └─ calc.py       # чистый движок расчёта (порт src/calc.ts)
```

## CORS

Разрешённые origin'ы задаются переменной окружения `ALLOWED_ORIGINS`
(через запятую). По умолчанию — `http://localhost:5173` (Vite dev-сервер).

## Маршрут (Шаг 2.1, MVP)

`ВходныеДанные.адресСтоянки` (точка отправления/возврата) и
`Заправка.адрес` (адрес АЗС из чека) — опциональные поля. Если заданы,
каждый `ПутевойЛист.маршрут` содержит текстовый список:
стоянка → АЗС по чекам этой смены в хронологическом порядке → стоянка.
Геокодинг и валидация «АЗС на маршруте» — следующие шаги.
