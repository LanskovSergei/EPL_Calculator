# Подключение фронта к бэкенду

## Что сделано

- **`src/api.ts`** — клиент к `POST /api/calculate`:
  - `calculateViaApi()` — прямой вызов бэкенда, приводит форму к формату,
    который ждёт pydantic (Set → массив для дней водителя, `''` → `null`
    для пустых числовых полей).
  - `calculateSmart()` — обёртка с фолбэком: если бэкенд физически
    недоступен (сеть/CORS/сервер не поднят) — тихо считает локально через
    `src/calc.ts` и добавляет предупреждение об этом в результат. Если
    бэкенд ответил ошибкой валидации (422) — это ошибка данных, а не
    доступности, поэтому показывается пользователю как обычное
    предупреждение, без отката на офлайн-движок.
- **`src/App.tsx`** — расчёт стал асинхронным (`await calculateSmart(data)`),
  кнопка «Посчитать» показывает «Считаю…» и блокируется на время запроса.
- **`src/types.ts`** — добавлены опциональные поля, зеркалящие бэкенд:
  `Заправка.адрес`, `ВходныеДанные.адресСтоянки`, `ПутевойЛист.маршрут`.
  Поля ввода адресов в форме пока не добавлены (это отдельная задача
  фронта — «Добавление поля адреса АЗС в форму»), но типы и вывод уже
  готовы принять эти данные, когда поля появятся.
- **`src/components/Results.tsx`** + `styles.css` — если у путевого листа
  есть `маршрут`, под карточкой выводится нумерованный список адресов.
- **`.env.example`** (корень репо) — `VITE_API_URL` для смены адреса
  бэкенда (по умолчанию `http://localhost:8000`).

## Как проверить локально

```bash
# терминал 1 — бэкенд
cd backend
python3 -m venv .venv && source .venv/bin/activate  # если ещё не создавал
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# терминал 2 — фронт
npm install
npm run dev
```

Открой http://localhost:5173, нажми «Заполнить примером из ТЗ» → «Посчитать».
Если бэкенд поднят — расчёт идёт через него. Останови `uvicorn` и нажми
«Посчитать» ещё раз — сработает откат на офлайн-движок с явным
предупреждением в результатах.

## Проверено

- `npx vite build` — сборка проходит без ошибок.
- Прямой TS-чек исходников (`tsc --noEmit` на файлах `src/`) — без ошибок.
- Живой запрос фронт→бэкенд с заголовком `Origin: http://localhost:5173` —
  CORS отдаёт `access-control-allow-origin` корректно, ответ содержит
  новое поле `маршрут`.

## Известный нюанс (не блокирует, не мой код)

`npx tsc -b` (сборка по `references` из `tsconfig.json`/`tsconfig.node.json`)
падает с `TS6310: Referenced project ... may not disable emit` — это
конфликт версии TypeScript 5.9 с исходной конфигурацией репозитория
(`tsconfig.node.json` имеет `composite: true` + `noEmit: true`), не связан
с изменениями этого шага. `npm run build` использует именно `tsc -b`, так
что при сборке через `npm run build` эта ошибка вылезет и у тебя — если
столкнёшься, скажи, поправим `tsconfig.node.json` (обычно решается снятием
`noEmit` в referenced-проекте или обновлением схемы конфигов Vite).
`npx vite build` (без `tsc -b`) работает нормально.
