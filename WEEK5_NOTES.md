# Неделя 5: интеграция с 1С (бэкенд)

## Важная оговорка

По плану Шаг 2.3 («Акт на списание ГСМ») распределён между разработчиками:
форма Акта — задача Разработчика 2 (неделя 4), а «Интеграция с 1С» —
моя задача (неделя 5). Поскольку готовой формы Акта от второго
разработчика в репозитории пока нет, я собрал **свой минимальный Акт**
прямо из результата расчёта (`app/act.py`) — достаточный, чтобы было что
синхронизировать с 1С и на чём протестировать сам адаптер интеграции.
Когда появится полноценная форма Акта (Разработчик 2) — маппинг на 1С
(`act_to_1c_payload`) нужно будет свести к её реальной структуре полей;
сам протокол обмена (OData) и код синхронизации меняться не должны.

## Что сделано

- **`app/act.py`** — `build_act()`: собирает `АктСписанияГСМ` (организация,
  ТС, период, построчно по каждому путевому листу: пробег/расход
  факт/норма, плюс итоговые суммы и экономия/перерасход) из результата
  `calculate()`.

- **`app/integration_1c.py`** — адаптер синхронизации с 1С через OData:
  - `is_configured()` — проверка `ONE_C_BASE_URL`.
  - `act_to_1c_payload()` — приводит Акт к плоской JSON-структуре,
    типичной для OData-документа 1С (поля с большой буквы, табличная
    часть отдельным массивом) — точный состав полей настраивается при
    подключении к конкретной базе.
  - `sync_act()` — `POST` на `{ONE_C_BASE_URL}/{ONE_C_ENTITY}` с Basic
    Auth (`ONE_C_USERNAME`/`ONE_C_PASSWORD`). Без настройки — тихо
    возвращает `None`, не блокируя получение самого Акта.
  - `OneCIntegrationError` — отдельное исключение для сетевых ошибок и
    отказов 1С, отличимое от «интеграция просто не настроена».

- **Эндпоинты**:
  - `POST /api/act` — только строит и возвращает Акт (JSON), 1С не трогает.
  - `POST /api/1c/sync` — строит Акт и пытается отправить в 1С; при
    отсутствии конфигурации возвращает `{"synced": false, "акт": {...}}`
    вместо ошибки — акт всё равно доступен пользователю.

- **Тесты** (`tests/test_1c_integration.py`, 6 шт. + 2 в `test_api.py`):
  сборка Акта и агрегация итогов, форма payload для 1С, поведение без
  конфигурации, успешная синхронизация и сетевая ошибка — на моках
  `httpx.MockTransport`, реальная база 1С не нужна.

Итого тестов в проекте: **99**, все зелёные.

## Как проверить

```bash
cd backend
pip install -r requirements.txt
pytest -v

uvicorn app.main:app --reload --port 8000
# POST /api/act или /api/1c/sync с телом ЗапросСинхронизации1С
# (пример — tests/test_1c_integration.py::make_sync_request)
```

## Когда появится реальная база 1С

1. Прописать `ONE_C_BASE_URL` (адрес OData/HTTP-сервиса), при
   необходимости `ONE_C_ENTITY`, `ONE_C_USERNAME`/`ONE_C_PASSWORD` в
   `.env` — код менять не нужно.
2. Свериться с реальной структурой принимающего документа в 1С и при
   необходимости поправить маппинг полей в `act_to_1c_payload()`
   (сейчас — условные русскоязычные ключи, ориентир по смыслу).
3. Заменить мой временный `build_act()` на реальную форму Акта, когда
   она появится от Разработчика 2 — протокол синхронизации не
   изменится.
